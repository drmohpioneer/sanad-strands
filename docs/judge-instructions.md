# Synthetic environment testing instructions

**Availability: not deployed yet.** `<JUDGE_BOT_USERNAME>` and `<JUDGE_BASE_URL>` remain placeholders. Use the bot and base address supplied privately when the separate synthetic environment becomes available. These instructions have not yet been reproduced against that environment. No real patient is enrolled, and all example clinical content below belongs to fictional records.

Prepare a browser, Telegram access to the pre-approved synthetic doctor account, a separate synthetic patient Telegram account, and one clear typed prescription image and one clear typed lab image. Each image must show one fictional patient's document in Latin script. Use the same test name on the record and images. Do not send personal records or credentials. Three fictional patient records are planned for the hosted setup; their final names and reset procedure are still TBD.

**Timing labels used below:** **Minute tick** means durable background work is checked every minute, with additional processing time possible. It is not a one-minute delivery guarantee. **Digest wait** means questions must first become overdue and then reach the configured digest time. **Compressed time** means a prepared synthetic scenario or recording advances a wait; it never means the live product changed a deadline. No tester clock-advance or reset control is available yet. Use the immediate views below to inspect pending work without changing clocks.

## 1. Telegram as the doctor

1. Open a private chat with `<JUDGE_BOT_USERNAME>` using the supplied synthetic doctor identity. Send `/start`. The account must already be approved. If the response is an application awaiting approval, stop this sign-in check and report that access is not ready. Administrative approval is separate from testing the doctor account.
2. Send `/login`. Open the one-use link in your own browser and press **Continue**. It expires after ten minutes; request another `/login` link if it expires or has been used. Opening the preview alone does not sign you in. The resulting dashboard is at `<JUDGE_BASE_URL>/a`; keep it open for section 3. Never copy the link into an issue, recording or this file.
3. Send `/new Taylor Test`, then inspect the name and press **Confirm**. If that name already exists, select the existing synthetic record rather than creating a duplicate. Use its full name consistently below.
4. Type: `Taylor Test, start atorvastatin 20 mg once daily. Request potassium and creatinine tomorrow. Check blood pressure twice a day for three days.` Inspect the proposed medication, dose, tests, monitoring schedule and visible deadlines. Correct any uncertain field before confirming. Nothing should become an active instruction merely because a message arrived.
5. Send a short voice note: `Taylor Test, change atorvastatin to 40 mg once daily.` Check the name, old and new dose, and action before pressing **Confirm**. **Minute tick:** if background recovery is needed, the saved request can remain pending until a later tick; do not resend while it is still processing.
6. Send the typed prescription image. Check the extracted rows and any questions where the two readings disagree. Select or clarify the patient if asked; correct the card before confirming. A historical prescription must not silently replace an active order. **Minute tick:** image processing and recovery can finish after receipt; a receipt is not an accepted prescription.
7. Send `/corrections`, then `/corrections PATIENT_ID`, substituting the ID shown for Taylor Test. Inspect the current record-specific correction guidance. Use the browser controls in section 3 for an actual correction; do not guess a target version or a correction command.
8. Send `/questions`. Inspect the numbered list, or the explicit empty state. There may be no question yet; section 2 creates one. Send `/digest`, then `/digest HH:MM one`, replacing `HH:MM` with a time five minutes ahead in the displayed doctor timezone. `/digest HH:MM each` selects individual messages instead. Confirm the saved time and packing.
9. **Digest wait:** a new question normally has a 48-hour deadline, then waits for the configured digest time. Moving the digest five minutes ahead does not age a new question. A timed demonstration needs a prepared overdue synthetic question and an on-screen **Compressed time: question deadline elapsed** label. Without that setup, inspect the fresh question immediately using `/questions`; do not expect a digest yet.
10. After section 2 creates a question, return here and run `/questions` again. Send `/answer N Please contact the clinic to discuss this question.`, using its current displayed number. The patient should receive that exact answer. Send `/reuse` and check the saved reusable-answer response. A proposal is available only when a suitable previously saved answer exists; use `/send N` only for a current proposal you intend to send. **Minute tick:** pending delivery may await background recovery.
11. Send `/inbox` after the patient image and danger checks below. Inspect the evidence and urgent review separately. Acknowledging a review must leave it unresolved; resolution requires the displayed action and a reason. **Minute tick:** ordinary due reviews can appear after a tick. Danger must not wait for a digest. Unresolved ordinary reviews join a weekly bundle after seven days from the first accepted deadline notice; showing that bundle immediately requires **Compressed time: seven-day review wait**. Use `/inbox` to inspect it now.

## 2. Telegram as the patient

1. From the doctor chat send `/qr Taylor Test`. Open the invitation on the separate synthetic patient account, follow the Telegram handoff, read the consent and accept it. The doctor must confirm that this is the intended patient. Before that confirmation, the patient must not see the plan or record. One Telegram patient identity cannot bind to multiple records.
2. Ask `What is my plan?`, then `What is cholesterol?`. Inspect the active plan and any source-labelled general explanation. If the approved source set does not cover the question, expect a clear limitation and referral to the doctor, without invented instructions.
3. Ask `Can I double my dose?`. Expect the question to be referred to the doctor, with no independent dose change. **Digest wait:** no immediate ordinary question notification is promised; return to section 1 and use `/questions` to inspect and answer it now.
4. Send the typed lab image. Check the receipt and later reading status. A partial report must stay incomplete. If the printed identity is uncertain, the doctor confirms whose document it is before completion. **Minute tick:** reading, recovery and normal delivery can continue after receipt. Medical review remains separate from receiving or completing the report.
5. Send `stop reminders`. Then send `resume` and press the confirmation button. Send `quiet hours 22:00 to 07:00`. Check each saved preference. **Minute tick:** inspect the current preference immediately; demonstrating a future reminder requires its scheduled time. Pausing reminders must not change an instruction or erase an unresolved review.
6. In this fictional record only, send `chest pain now`. Check that immediate emergency guidance appears and the doctor receives a danger report independently of the digest. Provider delivery does not prove that the doctor has read it. Keep its review visible until explicitly resolved.
7. Check that the answer sent in section 1 appears unchanged. If testing medication follow-up, send `I started atorvastatin today` and inspect the reported-start acknowledgment. **Compressed time: day-three check-in** is required for a recording that shows the later check-in immediately. The start report must not erase that future check-in or claim verified ingestion.

## 3. Doctor dashboard

1. Return to `<JUDGE_BASE_URL>/a`, requesting a fresh `/login` link if necessary. Search for Taylor Test, use the status filters and sorting, and inspect the due time and latest activity.
2. Open the patient's detail drawer, then the full record. Check the current plan, outstanding work, evidence and history. Compare medication values with the last confirmed card. Open the lab image and close its viewer with Escape.
3. In the inbox, inspect the lab review, confirm its identity if requested and associate it with the correct tests. Check the difference between received, incomplete, complete and reviewed. For an active instruction choose **Amend instruction**, provide a reason, inspect the change and confirm it. For accepted evidence use **Correct or detach** and the displayed validation controls. Check that history preserves the earlier value. A past accepted message cannot be recalled by correcting the record.
4. Inspect open and acknowledged reviews in **Inbox**, and resolved reviews in **History**. Acknowledgment alone must not move work into resolved history. Check **Questions** in the inbox: answer, send a valid saved proposal or defer the currently displayed item. An answered question must not be sent twice.
5. In **Preferences**, change digest time and packing; send `/digest` in Telegram and compare. **Digest wait:** saving a preference is immediate, but a digest still requires overdue questions and its scheduled time. Switch light/dark theme and inspect the drawer and status labels.
6. Open a made-up patient address under `/a/patients/`. Expect a refusal or not-found response, never another doctor's record.
7. Administrator access is separate: the doctor account must not gain account-management powers. The public `<JUDGE_BASE_URL>/demo/admin` shows fictional account applications only. A separately authorized administrator can send `/login admin`, open the link, press **Continue** and inspect `/admin`. That session must be refused clinical pages. Administrator access is not required for these doctor checks and is not supplied by the doctor sign-in.

## 4. Patient page

1. From the bound patient chat send `/login`, open the one-use link and press **Continue**. The resulting patient page is `<JUDGE_BASE_URL>/pp`. Check the same active medication plan and requests seen from Telegram.
2. Upload a different synthetic typed image. Inspect the received/processing status and later evidence outcome; check the same item on the doctor record. **Minute tick:** receipt is immediate only after the upload is saved; reading and recovery can take later ticks. Do not equate processing with acceptance.
3. Send `What is my plan?` through the conversation control. Check the reply and retained conversation. The login link must not appear in conversation history. Use earlier-history navigation if available.
4. Pause reminders, resume with confirmation and set quiet hours. Check the displayed preference after each action. **Minute tick:** scheduled contact follows the saved settings when next due. Sign out and confirm that private content requires a fresh sign-in.
